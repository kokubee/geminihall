# GeminiHall

AI の回答に含まれる主張を、検索で実際に取得した資料と照合して「誤りを確認」「根拠で裏付け」「判定を保留」のいずれかに分け、その工程を記録する Chrome 拡張機能と公開辞典です。

公開辞典: https://geminihall.cc

デモ動画（約30秒・音声なし）: [`docs/demo.mp4`](docs/demo.mp4)

名前は、Gemini の回答にハルシネーション（もっともらしい誤り）が多いと感じたことに由来します。監査の対象は Gemini に限らず、どの AI の回答でも使えます。

## 考え方（非オラクル原則）

- 監査に使う AI を、正解を知っている存在として扱いません。監査中に実際に取得した資料で裏付けられない限り、「誤り」とも「正しい」とも断定しません。
- 主張を小さな単位に分け、それぞれを資料と照合し、判定または判定の保留に至るまでの工程（`audit_trace`）をすべて表示します。
- 根拠が足りない主張、意見や価値判断、未来の予測は「判定を保留」とし、その理由を示します。
- 根拠の URL は、監査中に検索ツールが実際に返したものだけを「取得確認済み」とします。AI が自分で書いた URL は信用しません。断定的な判定に取得確認済みの根拠が1件もなければ、判定を保留に格下げします。
- 情報の種類ごとに有効期限（30日、24時間、1時間、再利用なし）を設け、期限を過ぎた結果は再確認が必要と表示します。
- 個人の監査結果は利用者のブラウザの中だけに置きます。公開辞典に載るのは、本人が公開に同意して申請し、管理者が根拠と個人情報の有無を確認して承認したものだけです。

## 構成

| ディレクトリ | 内容 |
| --- | --- |
| `apps/extension` | Chrome 拡張機能（WXT、Manifest V3）。サイドパネル、右クリックメニュー、監査の実行、キャッシュ、公開申請、DEMO モード、ChatGPT ログイン |
| `apps/api` | Cloudflare Workers + D1。公開事例の照会、公開申請の受付、管理者の審査 API。公開辞典もこの Worker から配信 |
| `apps/web` | 公開辞典と審査画面（Vite、フレームワークなし） |
| `packages/schema` | 監査結果の Zod スキーマと不変条件 |
| `packages/audit-core` | 監査の中核。Claude と OpenAI のアダプター、根拠 URL の照合、格下げ、キャッシュキー |
| `packages/eval` | 20件の評価セットと4指標の測定 |

仕様の正本は [`SPEC.md`](SPEC.md)、実装の進め方と規約は [`CLAUDE.md`](CLAUDE.md) です。

## 使い方

監査は、次の2つの方法で実行できます。どちらも監査は利用者の契約で実行し、GeminiHall のサーバーへキーやトークンを送りません。

- **ChatGPT のサブスク（Plus / Pro）でログイン**: API キーは不要です。設定で「ChatGPT（サブスクでログイン）」を選び、「Continue with ChatGPT」からログインします
- **自分の API キー（Anthropic / OpenAI）**: 設定で AI を選び、キーを入力します

1. 依存関係を入れてビルドします。

   ```bash
   pnpm install && pnpm --filter @geminihall/extension build
   ```

2. Chrome で `chrome://extensions` を開き、デベロッパーモードを有効にして、`apps/extension/.output/chrome-mv3` を「パッケージ化されていない拡張機能」として読み込みます。
3. ツールバーの GeminiHall からサイドパネルを開き、設定で使う AI を選びます。ChatGPT のサブスクを使う場合はログインします。
4. 確かめたい文章を貼り付けるか、Web ページ上で選択して右クリックし、「GeminiHall で根拠を監査」を選びます。

### ChatGPT のサブスクで使う場合の注意

- ログインで受け取った情報はメモリ上にだけ置き、ディスクには保存しません。ブラウザを閉じたときや拡張機能を更新したときは、もう一度ログインが必要です。
- 監査の利用枠は、あなたの ChatGPT プランの利用状況に含まれます。
- この方式は OpenAI のアカウント認可を利用しています。OpenAI 側の仕様変更により、使えなくなることがあります。詳しくは `SPEC.md` 第9章を参照してください。

### API キーの扱い

- キーは `chrome.storage.session` にだけ保存し、GeminiHall のサーバーへは送りません。監査は拡張機能から各社の API へ直接接続して行います。
- キーは、ブラウザを閉じたとき、拡張機能を更新・再読み込みしたとき、「このAIのキーを消す」を押したときに消えます。消えたキーは復元できないため、別の場所に控えておいてください。
- 利用料は利用者のアカウントに請求されます。GeminiHall 専用のキーを作り、使える金額に上限を設定することをおすすめします。

## 評価

`packages/eval` に、一次資料で正解を確認した20件の評価セットがあります（事実誤認8件、正しい主張5件、根拠不足・意見・予測5件、キャッシュ境界2件）。統計的な性能保証ではなく、監査の工程が設計どおりに働くかを確かめるためのものです。

2026年10月16日、OpenAI（`gpt-6-astra`）で全件を実行した結果:

| 指標 | 結果 | 目標 |
| --- | --- | --- |
| 誤訂正率（正しい主張・根拠不足を誤りと断定した割合） | 0%（0/10） | 0% |
| 判定保留の適切性 | 100%（5/5） | 高いほどよい |
| 根拠の実在・対応確認率 | 82%（23/28） | 高いほどよい |
| 誤キャッシュ率 | 0%（0/3） | 0% |
| 誤り検出率（補助） | 100%（8/8） | — |

10月15日の実行では、意見（「寿司は世界で最もおいしい料理である」）を入力エラーとして返した1件があり、意見・価値判断・予測は判定保留とする方針に改めたうえで全件を再実行しました。根拠の実在・対応確認率は、監査が引用したURLを評価側で再取得してスニペットと突き合わせた値で、JavaScriptで描画されるページや自動取得を遮断するページでは低く出ます。詳細は [`packages/eval/reports`](packages/eval/reports) を参照してください。

```bash
pnpm --filter @geminihall/eval eval --dry-run
```

実際に AI を呼んで評価する場合は `--provider OPENAI --yes` などを付け、環境変数でキーを渡します（利用料が発生します）。

## 開発

```bash
pnpm install
pnpm -r test
pnpm --filter @geminihall/extension e2e
```

公開辞典をローカルで確認する場合は、`apps/web` をビルドしてから `apps/api` で `wrangler dev` を実行します。
